# 零样本视觉文档检索

## 一、选题介绍

### 1.1 研究背景

随着数字化文档的爆发式增长，从海量文档中高效检索目标信息成为亟需解决的实际问题。传统文档检索方法依赖 OCR（光学字符识别）将文档内容转化为纯文本，再通过文本索引完成检索。然而，现实世界中的文档往往包含复杂版式、表格、图表、图片以及跨区域排版等丰富的视觉信息，纯文本表示不可避免地丢失这些关键信息，导致检索质量下降。

近年来，视觉语言模型（Vision-Language Models, VLMs）的快速发展为文档理解提供了新思路。ColPali 是其中一种代表性方法，它将文档页面直接作为图像输入多模态模型进行编码，无需 OCR 预处理，即可实现端到端的页面级检索。ColPali 采用 late interaction 机制（类似 ColBERT），在查询 token 和页面 patch 之间计算细粒度的 MaxSim 相似度，兼顾了检索精度与效率。

### 1.2 任务目标

本项目基于 ColPali 模型和 MMLongBench 数据集，完成以下目标：

1. **基础任务**：构建完整的 ColPali-based 页级检索系统，包含文档预处理、索引构建、查询编码与相似度排序，并在标准指标（Recall、Precision、MRR、nDCG）下评估性能；
2. **进阶任务**：在基础系统之上，设计并实现一种原创的改进方法，在检索性能或计算/存储效率方面取得提升。

### 3.2 详细计划

#### Phase 1：文献调研与环境准备（5.8 – 5.12）

**目标**：建立对任务的全面理解，搭好可运行的开发环境。

**论文阅读**：

- ColPali: _Efficient Document Retrieval with Vision Language Models_（核心方法）
- ColBERT: _Efficient and Effective Passage Search via Contextualized Late Interaction_（理解 late interaction 机制）
- 了解 MMLongBench 数据集的组成与标注方式

**环境搭建**：

- 配置 Python 3.10 + PyTorch + Transformers + colpali-engine
- 安装 pdf2image + poppler（PDF 转图像工具链）
- 下载 ColPali-v1.3 预训练权重（HuggingFace）
- 下载并初步探索 MMLongBench 数据集

#### Phase 2：基础系统实现（5.13 – 5.22）

**目标**：实现完整的 ColPali-based 页级检索管线。

**模块 1 — 文档预处理（成员 A）**：

- 将 MMLongBench 中的 PDF 文档按页转换为图像（统一分辨率）
- 设计页面元信息管理结构（doc_id, page_idx, image_path）
- 实现批量预处理脚本，支持增量处理

**模块 2 — 索引构建（成员 A）**：

- 使用 ColPali 对每一页图像进行编码，获取 patch-level embeddings
- 设计索引存储格式（torch tensor / numpy memmap）
- 支持离线构建 + 索引持久化 + 增量更新

**模块 3 — 查询编码与检索（成员 B）**：

- 使用 ColPali 的文本编码器对查询进行编码
- 实现 MaxSim 相似度计算：对查询中每个 token，找到页面 patch 中最高相似度，取所有 token 的 MaxSim 之和
- 实现 Top-k 排序（k = 1, 3, 5, 10）

**模块 4 — 评测系统（成员 B）**：

- 实现 Recall@k、Precision@k、MRR、nDCG@k 四项指标
- 构建自动化评测脚本，支持批量评测与结果汇总

#### Phase 3：基础评测与调优（5.23 – 5.25）

**目标**：完成基础系统的全面评测，生成 Milestone 报告。

- 在 MMLongBench 测试集上运行完整评测
- 分析不同 k 值下各指标的变化趋势
- 分析检索失败的典型案例，识别基线系统的薄弱环节
- 记录索引构建时间、存储空间、单次检索延迟等效率指标
- 撰写进展报告（Milestone 截止：5.28）

#### Phase 4：进阶方法研究与实现（5.26 – 6.2）

**目标**：设计并实现一种原创的改进方法，通过实验验证有效性。

我们计划从以下两个方向中选择一个作为主要改进方向（最终方向将在 Phase 3 的失败分析基础上确定）：

**候选方向 A — 查询感知的自适应索引压缩**：

- **动机**：ColPali 为每页生成大量 patch embeddings（通常 1024 个 × 128 维），索引存储开销大
- **方法**：训练一个轻量级的 patch 重要性评分器，根据 patch 的信息熵或与全局表示的偏离度，为每页仅保留 top-m 个最具信息量的 patch embeddings
- **目标**：在保持检索性能（Recall@5 下降 ≤ 2%）的前提下，将索引存储缩减 50% 以上

**候选方向 B — 两阶段粗精检索**：

- **动机**：MaxSim 计算开销随文档规模线性增长，大规模场景下检索延迟较高
- **方法**：第一阶段使用页面全局表示（patch embeddings 的均值池化）进行粗筛，快速获取候选集（top-50）；第二阶段在候选集上使用完整的 MaxSim 精排
- **目标**：在保持检索精度的前提下，将检索延迟降低 3-5 倍

**实验设计**：

- 基础 ColPali vs. 改进方法的指标对比（Recall、Precision、MRR、nDCG）
- 效率对比（检索延迟、索引大小、显存占用）
- 消融实验（验证改进中各组件的贡献）
